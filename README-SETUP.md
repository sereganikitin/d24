# ds24-kiosk

Android-приложение "инфопанель" для входной группы ЖК: открывает веб-версию
личного кабинета Диспетчер24 (`lk.purehome.ru`) в альбомном полноэкранном
kiosk-режиме, не даёт экрану гаснуть и не даёт выйти из приложения.

Два варианта сборки (build flavor `mode`):

- **dev** — для тестирования на личном телефоне. Не перехватывает кнопку
  Home, не запускается автоматически после перезагрузки, не ставится в
  Screen Pinning автоматически. `applicationId` — `ru.uk.ds24kiosk.dev`,
  ставится рядом с боевой сборкой, не конфликтует с ней.
- **kiosk** — боевая сборка для планшета на входе. Полный набор: landscape +
  fullscreen + Screen Pinning + автозапуск после перезагрузки + замена
  Home-экрана + автоперезапуск при крэше.

## Голосовой помощник (пилот — заказ гостевого пропуска на машину)

Кнопка-микрофон в левом нижнем углу экрана (напротив скрытой зоны
обслуживания в правом нижнем). Житель нажимает, говорит запрос, помощник
сам открывает "Заказать пропуск → На въезд" и заполняет поля — но
**кнопку "Заказать" всегда нажимает житель сам**, помощник ничего не
отправляет автоматически.

Устройство: распознавание речи и озвучка ответа — штатные Android API
(`SpeechRecognizer`/`TextToSpeech`, `ru-RU`), без сторонних SDK. Нужен
`RECORD_AUDIO` — приложение спросит разрешение при первом нажатии
кнопки. Убедитесь, что на планшете в Settings → Text-to-Speech стоит
русский голос — без него озвучка молча не сработает (текст на экране не
показывается, только произносится).

"Мозги" — backend-прокси на `/backend` в этом репозитории (Node/Express,
задеплоен на 72.56.12.105, `d24-voice.infoseledka.ru`; не Cloudflare —
у него бывают перебои с доступностью в России без VPN). Провайдер —
**YandexGPT**, не Gemini/Claude: у обоих Россия не входит в список
доступных регионов API, а backend физически стоит в России — запросы
отклонялись бы независимо от того, где выпущен ключ (детали и как
сменить провайдера позже — `backend/README.md`).

Чтобы помощник заработал, нужны ещё два шага снаружи этого репозитория:
1. В панели Timeweb добавить DNS A-запись `d24-voice.infoseledka.ru → 72.56.12.105`.
2. Вписать реальные `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` в
   `/var/www/d24-voice-assist/backend/.env` на сервере (получаются в
   [Yandex AI Studio](https://aistudio.yandex.ru/)), затем
   `pm2 restart d24-voice-assist`.

Первая версия понимает только один сценарий — гостевой пропуск на
машину (На въезд → Гостевой). Пешеходные пропуска, заявки, показания
счётчиков — следующие шаги, когда будут перед глазами соответствующие
экраны.

## Правки стилей применяются без пересборки APK

`kiosk-inject.css`/`.js` при каждой загрузке страницы сначала пытаются
скачаться с GitHub (`raw.githubusercontent.com/sereganikitin/d24/main/...`),
и только если сети/репозитория нет — используется копия, зашитая в APK
при сборке (`KioskStyleInjector.kt`). Это значит: чтобы поменять внешний
вид, достаточно поправить файл в `app/src/main/assets/`, закоммитить и
запушить — все уже установленные киоски подхватят изменение сами, без
новой сборки и переустановки. Два нюанса:

- **Нужен публичный репозиторий** — приложение скачивает файлы анонимно,
  без токена. Сам код приложения при этом виден всем, но ничего секретного
  в нём нет (проверено перед публикацией) — разве что ПИН обслуживания по
  умолчанию, который и так стоит сменить перед боевой установкой.
  Сделать репозиторий публичным: GitHub → Settings репозитория → в самом
  низу Danger Zone → Change visibility → Make public.
- **Кэш GitHub** — raw.githubusercontent.com отдаётся через CDN с кэшем
  на несколько минут, так что правка применяется не мгновенно, а обычно
  в пределах ~5 минут после пуша (плюс кто-то должен зайти на другой
  экран и вернуться на главный, либо просто подождать следующей
  перезагрузки WebView).

## Сборка APK через Codemagic (без Android Studio на этом компьютере)

В проекте уже есть `codemagic.yaml` и рабочий Gradle wrapper (скачан
официальный `gradle-wrapper.jar`, не сгенерирован вручную) — сборка в
облаке настроена и готова.

1. Создать репозиторий на GitHub (или GitLab/Bitbucket, если Codemagic у
   вас подключён к нему) и запушить туда этот проект. На этом компьютере
   для GitHub нет рабочего SSH-ключа (проверено — есть ключи только под
   другие серверы), так что проще всего через HTTPS:
   ```
   git remote add origin https://github.com/<ваш-логин>/ds24-kiosk.git
   git push -u origin main
   ```
   При пуше Git спросит логин/пароль — вместо пароля нужен Personal
   Access Token (GitHub → Settings → Developer settings → Personal
   access tokens → Fine-grained token с правом Contents: Read and write
   на этот репозиторий).
2. В Codemagic: Add application → выбрать этот репозиторий. Codemagic
   сам увидит `codemagic.yaml` в корне и предложит workflow
   `ds24-kiosk-debug`.
3. Запустить сборку (Start new build). По готовности в интерфейсе
   Codemagic появится ссылка на артефакты — два APK:
   `app-dev-debug.apk` (для теста на личном телефоне) и
   `app-kiosk-debug.apk` (боевой вариант для планшета). Также придёт
   письмо на почту с уведомлением о готовности сборки.
4. Скачать `app-dev-debug.apk` на телефон и установить (может
   понадобиться разрешить установку "из неизвестных источников").

Дальше при каждом изменении кода: закоммитить, `git push`, запустить
сборку в Codemagic заново (или настроить автосборку по пушу в
Codemagic → Workflow settings → Triggering).

## Открыть проект в Android Studio (если всё же понадобится)

Открыть папку `ds24-kiosk` в Android Studio (File → Open). При первом
Sync студия предложит скачать недостающие компоненты SDK (compileSdk 34) —
согласиться. Если студия предложит миграцию AGP/Gradle на более новую
версию — соглашаться безопасно, проект не завязан на конкретный патч.

Собрать/запустить нужный вариант: `Build Variants` → выбрать `devDebug`
(для теста на своём телефоне) или `kioskDebug`/`kioskRelease` (для
планшета).

## Тест на своём смартфоне (без физического доступа к планшету)

1. Выбрать `devDebug`, запустить на телефоне.
2. Приложение откроется в альбомной ориентации на весь экран, экран не
   будет гаснуть, пока открыто приложение.
3. Пройти вход по номеру телефона + SMS-код от сервисного аккаунта УК —
   проверить, что после перезапуска приложения сессия сохраняется
   (повторный вход не требуется).
4. Долгий тап (3 сек) в правом нижнем углу экрана → диалог с ПИН
   (по умолчанию `2468`, см. `ADMIN_PIN` в `app/build.gradle.kts`) → меню
   обслуживания (обновить страницу / Wi-Fi / вернуться в киоск-режим).
5. В `devDebug` кнопка Home и системная навигация работают как обычно —
   специально не блокируются, чтобы не мешать личному телефону.

## Установка на планшет в лобби (когда будет физический доступ)

1. Собрать `kioskRelease`, установить APK.
2. Разрешить игнорировать оптимизацию батареи (появится системный запрос
   при первом запуске), в системных настройках экрана выставить
   максимальный таймаут блокировки/"никогда".
3. Через админ-жест (см. выше) один раз пройти вход по телефону+SMS от
   сервисного аккаунта УК.
4. При первом `startLockTask()` система может показать диалог
   подтверждения Screen Pinning — подтвердить один раз.
5. Проверить: перезагрузка планшета → приложение поднимается само в
   альбомном режиме, кнопки Back/Overview/Home не дают выйти.
6. Если нужно снять киоск полностью (перепрошивка, обновление ОС) —
   админ-жест → ПИН → "Вернуться в киоск-режим" не выбирать, вместо этого
   долгим удержанием Back+Overview снять системный Screen Pinning (либо
   через ADB `adb shell am task lock stop`, если есть доступ).

## Перевёрстка того, что приходит с lk.purehome.ru

Сайт — обычная адаптивная React/MUI-страница (брейкпоинты на ширинах
768/992/1200px), не наше приложение её версткой не блокирует. Есть два
уровня подгонки под киоск:

1. **Автоматическая адаптация сайта под ширину экрана.** Это уже
   работает "бесплатно" — сайт сам переключает раскладку в зависимости
   от ширины viewport'а. Важный нюанс: на телефоне в альбомной ориентации
   эффективная CSS-ширина обычно ~700–900px — это ещё "узкий" брейкпоинт
   сайта (более компактная раскладка). На реальном планшете в лобби
   (обычно 1200px+) сайт переключится на более широкую/"десктопную"
   раскладку — то, что сейчас видно на телефоне, не обязательно то, что
   будет на планшете. Поэтому часть вопросов адаптивности снимется сама
   при тесте на настоящем устройстве.

2. **Свои правки поверх сайта** — `app/src/main/assets/kiosk-inject.css`.
   После каждой загрузки страницы (`MainActivity.onPageLoaded` →
   `KioskStyleInjector`) в `<head>` добавляется наш `<style>` со стилями
   из этого файла — можно укрупнять шрифты/кнопки, скрывать блоки
   (`display: none`), менять порядок через CSS `order` в
   flex/grid-контейнерах. Правится только CSS-файл, пересборка Kotlin не
   нужна.

   **Важное ограничение**: у MUI/emotion (движок стилей сайта) классы
   вида `css-1qrqqxz` генерируются заново при каждой пересборке сайта
   вендором — селекторы на них ломаются без предупреждения при любом их
   обновлении. Надёжные точки опоры — семантические классы вида
   `MuiButtonBase-root`, `MuiTypography-h1`, теги, `aria-*`/`role`
   атрибуты, текстовое содержимое. Точечные "скрыть этот блок"/"переставить
   вот эти два блока местами" правила добавляются по факту — нужны
   скриншоты или HTML реальных экранов (заявки, показания и т.п.) после
   входа, чтобы взять правильные селекторы, а не гадать.

3. **`app/src/main/assets/kiosk-inject.js`** — там, где одного CSS не
   хватает (нужно найти конкретную секцию по тексту заголовка, а не по
   классу). Первая правка уже внутри: на главном экране картинки в блоке
   "Актуальное" ужимаются до 56px высотой, в "Услуги" — до 92px, плюс в
   CSS у заголовков секций убраны лишние отступы — всё это, чтобы главный
   экран помещался на планшете без прокрутки. Числа (56/92px) — первая
   прикидка, без реального разрешения планшета под рукой; после теста на
   настоящем устройстве их почти наверняка нужно будет подправить в этом
   же файле (пересборка Kotlin не нужна, только пересборка через
   Codemagic/GitHub Actions).

   Туда же добавлен редизайн боковой панели (карточка "К оплате",
   карточка помещения, 5 быстрых действий) под фирменную палитру Pure —
   белый / тёплый чёрный (#201B16) / кофейно-коричневый (#6B4F36) как
   единственный акцент; "Экстренный вызов" — намеренно отдельным
   терракотовым (#C1512E), как сигнал безопасности, не смешанный с
   акцентом бренда. Макет для сверки:
   https://claude.ai/code/artifact/6c742d8a-cec7-482e-8884-bc0edec65a1a
   Список действий превращён в сетку 2×2 сменой `display` у общего
   родителя (без переноса DOM-узлов, чтобы не потерять обработчики
   кликов сайта) — если у сайта окажется другая структура и это не
   сработает, строки просто останутся вертикальным списком, но
   перекрашенными.

4. **Модалки (пропуска, обращения и т.п.) дорисовываются в DOM позже**,
   без перезагрузки страницы — обычная логика "один раз после загрузки"
   их не видит. Поэтому теперь `kiosk-inject.js` ставит `MutationObserver`
   на `document.body` и переприменяет все правила при любом изменении
   DOM (с дебаунсом 150мс). Первая правка на этой основе — в модалке
   "Заказать пропуск → На въезд" скрыта кнопка "Постоянный" в
   переключателе "Срок действия" (постоянных пропусков на авто по факту
   быть не должно). Тот же механизм понадобится дальше для голосового
   помощника — ему тоже нужно будет видеть и заполнять поля, которые
   появляются в модалках.

## Автовозврат на главный экран

Если кто-то оставил планшет открытым на вкладке "Помещение"/"Обращения"/
"Платежи" и минуту (60 сек) никто не касался экрана — приложение само
перезагружает главный экран (`MainActivity.checkIdleReturn`, таймаут —
`IDLE_TIMEOUT_MS`). Главный экран запоминается автоматически по первому
URL, в котором встречается `/main` (так выглядит адрес главной страницы
после входа — `lk.purehome.ru/<id>/main/category`). Если понадобится
другой таймаут — поменять `IDLE_TIMEOUT_MS` в `MainActivity.kt`.

## Известные ограничения этой версии

- Без Device Owner Screen Pinning менее надёжен, чем полноценный kiosk
  через MDM: теоретически пользователь может выйти через комбинацию
  системных жестов (удержание Back+Overview), это стандартное системное
  поведение Android, отключить которое можно только через Device Owner.
- Автологин по SMS не автоматизирован (не читаем SMS) — вход выполняется
  вручную один раз через админ-меню сотрудником УК.
- Голосовой ИИ-агент и умный дом не реализованы — в коде оставлена точка
  расширения (`webview/AndroidBridge.kt`, JS-мост `window.DS24Kiosk`) для
  следующего этапа.
